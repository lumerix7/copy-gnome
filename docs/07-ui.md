# 07 - UI

## Centered popup (the main UX) - answers brief #5

Triggered by the global shortcut (default `<Super>v`). The **same widget** is also opened by
the panel indicator (see below); the only difference is placement - `show()` takes a
`{ placement: 'center' | 'panel', anchorActor }` option and everything else (styling,
opacity, search, number quick-paste, clear, keyboard logic) is shared. Behavior:

- Center on the focused window's monitor, falling back to GNOME Shell's current monitor.
- The shortcut-centered popup starts centered and can be moved by dragging its small top
  handle. The panel-indicator popup stays anchored to the status icon and is not movable.
- Near-caret anchoring is intentionally disabled. GNOME/Wayland caret reporting was not
  stable across apps or repeated modal grabs.
- Position knobs: `popupOffsetX/Y` and `popupEdgeMargin`.
- Visual knobs: `popupWidth`, `popupMaxHeight`, `popupOpacity`, and `popupTheme`
  (`auto`, `dark`, or `light`). Width/height automatically shrink on small monitors.
- Implemented as an `St.Widget`/`St.BoxLayout` added to `Main.layoutManager.uiGroup`,
  shown with a **modal grab** (`Main.pushModal()`), so keyboard nav works and Esc/outside
  panel click dismisses it. (A `BoxPointer` may be used for the panel-anchored variant.)
- Remember the **previously focused window** before grabbing, to restore focus (and
  enable auto-paste) on close.


### Layout

```
┌─ Copy GNOME ───────────────┐
│ 🔍 [ search...         ]   │   ← / focuses search
│ ↑↓/jk move · 1-N pick · ...│   ← always-on hint cheat sheet
├────────────────────────────┤
│ 1  Hello world             │   ← row number = quick-pick
│ 2  https://example.com     │
│ 3  06-28 12:36  [image 3 KB] │
│ 4  /home/u/file.pdf  (file)│
│ ...                        │
├────────────────────────────┤
│              Clear history │   ← footer button (shared by both windows)
└────────────────────────────┘
```

When the list is empty the body shows `(empty)`; when a search filters everything out it
shows `(no matches)`.


### Keyboard (as implemented)

- Open → popup receives keyboard focus; **the first (most-recent) row is pre-selected**, so
  pressing `Enter` immediately pastes the top entry.
- `/` focuses the search field. `Ctrl+F` is still accepted as a compatibility shortcut, but
  the visible popup hint uses `/`.
- While search is focused or contains a query, the hint row switches to search guidance and
  does not advertise number quick-paste. In search mode, `Esc` clears the query and returns
  focus to the list; a second `Esc` closes the popup.
- `Ctrl+S` manually flushes pending history to storage. This is popup-local, not a global
  shortcut, and is intentionally not listed in the always-visible hint row.
- `↑`/`↓` or `j`/`k` move the selection; `Enter`/`KP_Enter` = restore selected + close
  (+ auto-paste). `j`/`k` navigation is active only while search is not focused, so those
  letters remain normal query text inside search.
- **Number quick-paste**: type a row number (`1`..`N`) to paste it; standalone `0` still
  means row **10**. Valid row numbers are highlighted with the same selected state as
  arrow navigation, and a small English hint says to keep typing digits or wait to paste
  after `numberPickTimeoutMs` (default 500 ms). Invalid numbers show a warning hint and
  cancel the pending paste. `Backspace` edits the pending row number. This is active while
  search is not focused; after `/` or `Ctrl+F`, digits go into the search query instead.
- Outside search mode, `Esc` closes without changing the clipboard.
- Clicking blank space inside the popup does not close it. Clicking outside the popup panel
  closes immediately. Delayed focus-loss close is intentionally not used; GNOME focus
  transitions during modal grabs are not stable enough to justify the extra watchers.
- `Delete` removes the highlighted entry. *(planned - not in M1)*
- There is **no separate row-count cap**. The popup renders the whole history and
  **scrolls** via `popupMaxHeight`. History is normally bounded by `history.maxItems`;
  the internal 64 MiB snapshot cap may trim older entries earlier for unusually large
  entries.


### Mouse (as implemented)

- **Hover = soft tint only** (CSS `:hover`); it does *not* move the keyboard selection, so a
  mouse resting near the list never fights arrow-key / number navigation.
- Dragging the small top handle moves only the shortcut-centered popup and clamps it inside
  the current monitor.
- **Single click = select + paste** (restore + close).
- **Right click on a row** opens a small item menu. `Paste` uses the same restore flow as
  single click / Enter / number quick-paste; `Remove` deletes that history entry and rebuilds
  the current list without closing the popup.
- For rich text (`kind=rich`) rows, the item menu also includes `Paste plain`.
  `Paste` follows `ui.richTextApps` / `ui.plainTextApps`; `Paste plain` forces the plain
  fallback even when the focused target matches `ui.richTextApps`. See
  [13-rich-text](13-rich-text/README.md).
- Every row except `kind=file` (URI references only, nothing to write) also offers
  `Save as` (`core/save.js`): the popup closes, the **XDG portal `FileChooser.SaveFile`
  dialog** opens (GTK dialogs cannot run inside `gnome-shell`; the portal process draws
  it, the extension only speaks DBus), and the record's payload is written asynchronously
  to the chosen target, ending in a Shell notification. Fail-closed: portal
  missing/cancel/timeout (10 min) or a failed write logs `[save]` and never throws into
  the Shell.
  - **Default name**: `clip-<kind>-YYYYMMDD_HHMMSS.<ext>` from the record's capture time
    (local), e.g. `clip-image-20260702_153012.png`.
  - **What is written + suffix policy**, per kind:
    - `text` - the plain payload, `.txt`;
    - `rich` - the primary rich payload; suffix by its mime (`text/html` → `.html`,
      `text/rtf`/`text/richtext` → `.rtf`, `text/markdown` → `.md`), plain fallback
      `.txt`. The plain twin is available via `copy-gnome get <id>`;
    - `image` / other binary - the decoded base64 payload; the stored `mime` wins via an
      explicit map (`image/png` → `.png`, `image/jpeg` → `.jpg`,
      webp/gif/bmp/tiff/svg/ico/avif/heic... ); an unknown mime falls back to magic-byte
      sniffing of the decoded payload (PNG/JPEG/GIF/WebP/BMP); if both fail the suffix is
      `.bin` - never guessed. In practice the monitor currently captures only `image/png`
      ([03-clipboard](03-clipboard/README.md)), so saved images are `.png` today.
- File (`kind=file`) rows offer `Show in Files` instead (`core/reveal.js`): reveal +
  select the record's uris in the **session default file manager** via the freedesktop
  `org.freedesktop.FileManager1.ShowItems` DBus interface - deliberately no file-manager
  config; the session default owns that bus name (Nautilus, Nemo, Dolphin, ...). If the
  call fails, fall back to opening the first uri's parent folder with the default
  handler.
  - **Existence is pre-checked** (async `query_info`, 1.5 s timeout per uri) so a stale
    record shows our own feedback instead of a file-manager error dialog. All uris
    missing → the popup stays open and shows the inline `File not found` hint; some
    missing → the existing ones are revealed and a Shell notification reports
    `N of M files no longer exist`. A check that times out (slow network mount) counts
    as existing and is left to the file manager.
  - Multi-uri records pass every existing uri to `ShowItems`; the file manager groups
    them per parent folder.
- **Clear history** footer button: clears the history, resets the search filter, and
  rebuilds the (now empty) list in place without closing the window. Mouse-only (not
  keyboard-focusable), so it never interferes with row navigation or number quick-paste.
- Additional per-row actions (copy-as-text, detail view) are *planned*, not in M1.

Every paste path (Enter, number, single-click, row-menu Paste) does the same restore flow:
validate the entry, normally write it to the **system clipboard**, **move it to the front**
(MRU), and - if `ui.autoPaste` is on (default) - inject Ctrl+V into the focused window. The
only configured exception is `ui.skipClipboardWriteForRecentTopSec`, which may skip just
the system clipboard write for a recent row-1 restore; MRU and paste behavior continue.


## Panel indicator

- `PanelMenu.Button` in the top bar (clipboard icon).
- Clicking it (any button / touch) opens the **same widget** as the global shortcut - one
  `Popup` instance, two callers. Search, number quick-paste, "Clear history", styling and
  all keyboard logic are identical. **The only difference is placement**: the shortcut
  centers the widget; the indicator anchors it under the icon (drops down, right-aligned).
  Both use the same `popupOpacity`, so transparency is *not* a difference.
- Right-clicking the panel icon opens a context menu with `Show` and `Clear history`.
  `Clear history` uses the same click-again confirmation pattern as the popup footer button.
- One config set for both (`popupWidth`, `popupMaxHeight`, ...); the legacy
  `indicatorMaxItems` / `indicatorMenuWidth` keys were removed.


## Preferences window (GUI)

- `prefs.js` using **Adw/Gtk4** (GNOME 46), opened via Extension Manager's gear button or
  `gnome-extensions prefs copy-gnome@clipboard`. It runs in a separate process from
  `gnome-shell`, so a crash here never touches the compositor.
- **Keybindings** writes GSettings (`toggle-popup`); all other editable pages write the active
  config file via a minimal YAML serializer: `config.yaml` by default, falling back to
  `config.json` only when a JSON config already exists and no YAML does. So GUI edits always
  take effect (first-time users with no config file get a `config.yaml`). Saving a YAML rewrites
  it (hand-written comments/formatting are dropped). History limits apply after disable/enable.
- Pages: **Keybindings** (keybinding capture), **History** (limits), **Storage** (payload caps
  and persistence), **UI** (layout/paste matching), and **General** (capture/logging/privacy/about).
- Config rows show two subtitle lines: description, then the current value as
  `section.field: value`. The copy icon copies those same two lines. Keybinding detail rows
  use the same pattern, but the second line is a full `GSETTINGS_SCHEMA_DIR=... gsettings set ...`
  command.


## Visual / theming

- `stylesheet.css` owns explicit popup color classes instead of relying on the ambient Shell
  theme.
- `ui.popupTheme` chooses the popup color theme. The default `auto` follows
  `org.gnome.desktop.interface color-scheme` first, falls back to Shell session mode if that
  cannot be read, and otherwise uses the dark popup. The dark theme is an
  explicit neutral charcoal gray (`#36363a`-style), not pure/bright black; hover, selected,
  border, and warning colors are tuned with low-saturation gray/soft red accents.
- `ui.showThumbnails` is reserved. The current Shell runtime does not decode thumbnails
  in the popup; image entries use a small text preview such as `[image 3 KB]`.
