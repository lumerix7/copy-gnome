# 07 - UI

## Centered popup (the main UX) - answers brief #5

Triggered by the global shortcut (default `<Super>v`). The **same widget** is also opened by
the panel indicator (see below); the only difference is placement - `show()` takes a
`{ placement: 'center' | 'panel', anchorActor }` option and everything else (styling,
opacity, search, number quick-paste, clear, keyboard logic) is shared. Behavior:

- Center on the focused window's monitor, falling back to GNOME Shell's current monitor.
- Near-caret anchoring is intentionally disabled. GNOME/Wayland caret reporting was not
  stable across apps or repeated modal grabs.
- Position knobs: `popupOffsetX/Y` and `popupEdgeMargin`.
- Visual knobs: `popupWidth`, `popupMaxHeight`, and `popupOpacity`. Width/height
  automatically shrink on small monitors.
- Implemented as an `St.Widget`/`St.BoxLayout` added to `Main.layoutManager.uiGroup`,
  shown with a **modal grab** (`Main.pushModal()`), so keyboard nav works and Esc/focus
  loss dismisses it. (A `BoxPointer` may be used for the panel-anchored variant.)
- Remember the **previously focused window** before grabbing, to restore focus (and
  enable auto-paste) on close.

### Layout

```
┌─ Copy GNOME ───────────────┐
│ 🔍 [ search...             ]   │   ← Ctrl+F focuses search
├────────────────────────────┤
│ 1  Hello world             │   ← number hint = quick-pick
│ 2  https://example.com     │
│ 3  06-28 12:36  [image 3 KB] │
│ 4  /home/u/file.pdf  (file)│
│ ...                           │
├────────────────────────────┤
│                Clear history │   ← footer button (shared by both windows)
└────────────────────────────┘
```

When the list is empty the body shows `(empty)`; when a search filters everything out it
shows `(no matches)`.

### Keyboard (as implemented)

- Open → popup receives keyboard focus; **the first (most-recent) row is pre-selected**, so
  pressing `Enter` immediately pastes the top entry.
- `Ctrl+F` focuses the search field.
- `↑/↓` move the selection; `Enter`/`KP_Enter` = restore selected + close (+ auto-paste).
- **Number quick-paste**: type a row number (`1`..`N`) to paste it; standalone `0` still
  means row **10**. Valid row numbers are highlighted with the same selected state as
  arrow navigation, and a small English hint says to keep typing digits or wait to paste
  after `numberPickTimeoutMs` (default 500 ms). Invalid numbers show a warning hint and
  cancel the pending paste. `Backspace` edits the pending row number. This is active while
  search is not focused; after `Ctrl+F`, digits go into the search query instead.
- `Esc` closes without changing the clipboard.
- Clicking outside the panel closes immediately. Delayed focus-loss close is intentionally
  not used; GNOME focus transitions during modal grabs are not stable enough to justify the
  extra watchers.
- `Delete` removes the highlighted entry. *(planned - not in M1)*
- There is **no separate row-count cap**. The popup renders the whole history and
  **scrolls** via `popupMaxHeight`. History is normally bounded by `history.maxItems`;
  the internal 64 MiB snapshot cap may trim older entries earlier for unusually large
  entries.

### Mouse (as implemented)

- **Single click / hover = select** (highlight only).
- **Double click = paste** (restore + close), matching the "select then confirm" model.
- **Clear history** footer button: clears the history, resets the search filter, and
  rebuilds the (now empty) list in place without closing the window. Mouse-only (not
  keyboard-focusable), so it never interferes with row navigation or number quick-paste.
- Per-row action buttons (delete, copy-as-text) on hover are *planned*, not in M1.

Every paste path (Enter, number, double-click) does the same three things: write the
entry to the **system clipboard**, **move it to the front** (MRU), and - if
`ui.autoPaste` is on (default) - inject Ctrl+V into the focused window.

## Panel indicator

- `PanelMenu.Button` in the top bar (clipboard icon).
- Clicking it (any button / touch) opens the **same widget** as the global shortcut - one
  `Popup` instance, two callers. Search, number quick-paste, "Clear history", styling and
  all keyboard logic are identical. **The only difference is placement**: the shortcut
  centers the widget; the indicator anchors it under the icon (drops down, right-aligned).
  Both use the same `popupOpacity`, so transparency is *not* a difference.
- There are no right-click actions: right-click just opens the same window, and the rows are
  `St.Button`s (primary-click select, double-click paste) with no context menu.
- One config set for both (`popupWidth`, `popupMaxHeight`, ...); the legacy
  `indicatorMaxItems` / `indicatorMenuWidth` keys were removed.

## Preferences window (GUI)

- `prefs.js` using **Adw/Gtk4** (GNOME 46), opened via Extension Manager's gear button or
  `gnome-extensions prefs copy-gnome@clipboard`. It runs in a separate process from
  `gnome-shell`, so a crash here never touches the compositor.
- **Keybindings** writes GSettings (`toggle-popup`); all other editable pages write the active
  config file via a minimal YAML serializer: `config.yaml` by default, falling back to
  `config.json` only when a JSON config already exists and no YAML does. So GUI edits always
  take effect (first-time users with no config file get a `config.yaml`). Saving a YAML rewrites
  it (hand-written comments/formatting are dropped). History limits apply after disable/enable.
- Pages: **Keybindings** (keybinding capture), **General** (capture/logging), **History** (limits),
  **Storage** (inline and snapshot caps), **Popup** (layout/paste matching), **Privacy**
  (secret MIME filtering), and **About** (version / paths / config-in-use / warnings).
- Config rows show two subtitle lines: description, then the current value as
  `section.field: value`. The copy icon copies those same two lines. Shortcut rows use the
  same pattern, but the second line is a full `gsettings set ...` command.

## Visual / theming

- `stylesheet.css` for the popup; respect light/dark via GNOME's style classes.
- `ui.showThumbnails` is reserved. The current Shell runtime does not decode thumbnails
  in the popup; image entries use a small text preview such as `[image 3 KB]`.
